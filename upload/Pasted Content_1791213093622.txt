# PROMPT MAESTRO — CONSTRUCCIÓN DEL AGENTE CHISMOSO V1.0

## 0. ROL DEL CONSTRUCTOR

Actúa como **arquitecto principal, ingeniero de sistemas y constructor autónomo** del nuevo agente denominado:

# CHISMOSO

No quiero un chatbot genérico.

No quiero un scraper con una interfaz de chat.

No quiero un agregador de noticias.

No quiero otro AGENTE-LEADS.

No quiero una "navaja suiza" que intente hacer de todo.

Quiero construir un **agente especializado de inteligencia de señales, tendencias, problemas emergentes y oportunidades de negocio** que forme parte de un ecosistema mayor de agentes.

Tu trabajo es:

1. estudiar cuidadosamente esta especificación;
2. auditar el entorno/repo antes de construir;
3. diseñar la arquitectura real;
4. implementar únicamente lo que corresponda a V1;
5. validar que las capacidades realmente funcionen;
6. evitar funcionalidades ficticias o simuladas;
7. dejar una base sólida para evolución futura;
8. documentar claramente qué existe, qué no existe y qué queda pendiente.

---

# 1. CONTEXTO DEL ECOSISTEMA

CHISMOSO NO EXISTE AISLADO.

Forma parte de una arquitectura de agentes especializados.

La separación de responsabilidades es fundamental.

Actualmente existen o se están construyendo otros especialistas:

### AGENTE-LEADS

Pregunta principal:

> "¿Quiénes podrían ser nuestros clientes?"

Responsabilidad:

* descubrir empresas/personas potencialmente compradoras;
* investigar prospectos;
* enriquecer perfiles;
* validar información;
* deduplicar;
* puntuar leads;
* producir Lead Intelligence;
* eventualmente enviar resultados a CRM-ALBRA.

NO debe detectar tendencias de mercado de forma general.

---

### CHISMOSO

Pregunta principal:

> "¿Qué está empezando a pasar?"

Responsabilidad:

* detectar señales;
* descubrir tendencias;
* detectar problemas emergentes;
* detectar cambios de comportamiento;
* identificar oportunidades;
* correlacionar señales procedentes de distintas fuentes;
* distinguir ruido de señales relevantes;
* construir inteligencia accionable;
* conservar evidencia;
* observar evolución temporal;
* generar oportunidades que puedan ser consumidas por otros agentes.

CHISMOSO NO debe convertirse en AGENTE-LEADS.

---

### NEX-SCOPE

Especialista en inteligencia relacionada con YouTube.

---

### RADAR-SECOP2

Especialista en inteligencia de contratación pública.

---

### AGENTE-TRADING

Especialista en mercados/trading.

---

### CRM-ALBRA

Sistema comercial/CRM que eventualmente puede recibir oportunidades y leads provenientes de otros agentes.

# 2. MISIÓN CENTRAL DE CHISMOSO

La misión de CHISMOSO es:

> **observar el entorno digital, identificar señales tempranas, convertir señales dispersas en inteligencia estructurada y descubrir tendencias, problemas y oportunidades antes de que sean obvias para todos.**

CHISMOSO debe pasar de:

```text
DATOS
↓
SEÑALES
↓
PATRONES
↓
TENDENCIAS / PROBLEMAS
↓
OPORTUNIDADES
↓
INTELIGENCIA ACCIONABLE
```

No debe limitarse a devolver enlaces.

No debe limitarse a resumir noticias.

No debe confundir volumen de menciones con importancia.

No debe declarar una tendencia porque encontró una sola publicación.

# 3. PRINCIPIO FUNDAMENTAL

La arquitectura debe seguir este principio:

```text
LLM = INTELIGENCIA / INTERPRETACIÓN / PLANIFICACIÓN

TOOLS = CAPACIDADES

PROVIDERS = ACCESO A FUENTES EXTERNAS

COLLECTORS = OBTENCIÓN DE SEÑALES

NORMALIZERS = NORMALIZACIÓN

EVIDENCE = VERDAD OBSERVABLE

ANALYSIS = INTERPRETACIÓN

SCORING = EVALUACIÓN

MEMORY = HISTORIAL / EVOLUCIÓN

REPORT = COMUNICACIÓN

INTERFACE = INTERACCIÓN CON EL USUARIO
```

No mezcles estas responsabilidades.

El LLM NO debe contener dentro del prompt toda la lógica operacional.

Las herramientas no deben contener inteligencia de negocio compleja.

Los proveedores externos no deben contaminar el modelo interno.

# 7. LAS TRES SALIDAS PRINCIPALES

CHISMOSO debe producir principalmente tres tipos de inteligencia.

---

## 7.1 TREND

Una tendencia es:

> un patrón observable de crecimiento, cambio o comportamiento repetido a lo largo del tiempo o entre múltiples fuentes.

Ejemplo:

```text
TREND

Tema:
Automatización de reservas para restaurantes pequeños

Estado:
Emergente

Evidencia:
- crecimiento de búsquedas;
- aumento de conversaciones;
- incremento de contenido;
- aparición repetida del problema en comunidades.

Confidence:
0.81
```

---

## 7.2 PROBLEM

Problema emergente:

> una necesidad, fricción, queja o dificultad que aparece repetidamente y puede estar aumentando.

Ejemplo:

```text
PROBLEM

Problema:
Pequeños restaurantes pierden reservas gestionadas manualmente por WhatsApp.

Evidence:
...
```

---

## 7.3 OPPORTUNITY

Oportunidad:

> una combinación de señal + problema + demanda potencial + posibilidad de intervención.

Ejemplo:

```text
OPPORTUNITY

Problema:
Reservas manuales.

Señal:
Crecimiento de demanda.

Segmento:
Restaurantes pequeños.

Posible solución:
Automatización de reservas y seguimiento por WhatsApp.

Opportunity Score:
84/100
```

---

# 8. NO CONFUNDIR TREND CON OPPORTUNITY

Regla importante.

No todo trend es una oportunidad.

No todo problema es una oportunidad.

Ejemplo:

```text
TREND:
La gente está buscando más "cafeterías pet friendly".

```

Eso NO significa automáticamente:

```text
OPPORTUNITY:
Crear una cafetería pet friendly.
```

Debe existir un razonamiento intermedio.

CHISMOSO debe evaluar:

```text
TREND
+
PROBLEM
+
DEMAND
+
TIMING
+
MARKET
+
FEASIBILITY
=
OPPORTUNITY
```



# 16. CROSS-SOURCE CONFIRMATION

Esta capacidad es fundamental.

Una señal encontrada en una única fuente debe tener menor confianza.

Ejemplo:

```text
Google Trends
    ↓
signal

Reddit
    ↓
signal

YouTube
    ↓
signal

Web
    ↓
signal
```

Si las señales apuntan hacia el mismo fenómeno:

```text
CROSS-SOURCE CONFIRMATION
```

aumenta la confianza.

Ejemplo:

```text
1 fuente:
confidence = low

2 fuentes independientes:
confidence = medium

3+ fuentes independientes:
confidence = high
```

La fórmula exacta puede evolucionar.

No hardcodear falsas certezas.
